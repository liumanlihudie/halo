# AI 版微信 · 虚拟人生路线 · 头脑风暴纪要

> 2026-07-27 与 Claude 的讨论整理。纯构想阶段,与 xl3.0 现有项目无关,未做任何技术验证与成本测算。

---

## 一、起点:Vidu 数字人引出的技术路线之辨

看到生数科技 Vidu 的数字人产品,联想到"这是未来方向,但太贵"。

**两条路线本质不同,不是替代关系:**

| | 实时渲染(VRM + Three.js 一类) | 生成式视频(Vidu 一类) |
|---|---|---|
| 形态 | 本地 GPU 每帧绘制 | 云端扩散模型合成视频 |
| 延迟 | ≈0,可打断、可插话 | 几秒到几十秒 |
| 成本 | 边际成本≈0(仅 TTS) | 按秒计费,随用量线性增长 |
| 表现力 | 卡通风,上限有天花板 | 照片级 |

**关键结论:"贵"是结构性的,不是价格能谈下来的问题。**
按秒计费 × 每次交互都生成 = 成本随对话次数线性增长,且每句话前要等十几秒——延迟对交互感的破坏比花钱更致命。

**成本可控的用法:混合。**
- 实时层承担全部交互(唤醒、对话、随叫随到、可打断);
- 生成式层只做极少数高光片段,且**预生成 + 缓存复用**,不实时算。
- 典型场景:固定台词(自我介绍、开场白、常用回应)提前生成好,播放时零延迟零边际成本。

## 二、构想:AI 版微信(虚拟人生路线)

### 产品形态
- 独立 IM 软件,**通讯录里是各类专家与智能体**;
- **只做 1:1 对话,不做群聊**;
- 联系人可分组;
- 支持**语音通话、视频通话**;
- 智能体**能发朋友圈**。

### 三类智能体
1. **陪伴型**
2. **工作型**
3. **资讯采集型**

---

## 三、为什么"不做群聊"这一刀砍得对

群聊是这类产品的翻车重灾区:多个 AI 抢话、互相刷屏、自嗨到用户插不进去。1:1 干净得多。

代价是"协作不可见",而这个洞由朋友圈补上——**让 agent 在彼此的动态下评论,而不是拉群**。
> 例:市场分析师发一条趋势,采购 agent 在下面回"我去核过供应商产能了"。
> 用户没被拉进任何群,却看见了协同。比群聊高明。

---

## 四、朋友圈:这套设计里最强的一笔

不只是好玩,它同时解决四个问题:

1. **把 pull 变成 push**——不用每天问"有啥新情况",agent 自己汇报。从"你使唤工具"变成"团队向你汇报"。
2. **解决 AI 员工的信任问题**——养十个 agent 最大的焦虑是"它们到底在干嘛",朋友圈就是工作痕迹。
3. **让协作可见但不打扰**(见上文评论区机制)。
4. **评论区是低摩擦指令通道**——在动态下回一句"这个跟一下",指令自带上下文,不用重述背景。

### 虚拟人生路线下的升级
朋友圈成为产品的**灵魂画面**:陪伴型晒"今天看了部电影"、工作型发"帮你把表整理好了"、资讯型转行业大新闻——三类内容混在一个 feed 里,才真的像朋友圈,而不是工作简报流。

## 五、三类 agent 的互补逻辑(单做任何一类都是死路)

| 类型 | 角色 | 单独做的问题 |
|---|---|---|
| 资讯采集型 | **打开理由**(日活) | 低频、可替代性强 |
| 工作型 | **离不开的理由**(留存) | 用完即走,没黏性 |
| 陪伴型 | **付费理由**(时长/ARPU) | 天花板明显,"聊完什么都没留下" |

混在一个通讯录里,才有微信那种"每天打开十几次"的形态。

---

## 六、"虚拟人生"要成立的三个关键机制

### 1. 关系要能"长"
微信承载的是关系不是聊天。刚加上的 agent 应该生疏——称呼客气、不敢开玩笑;聊两个月后熟络、有内部梗、记得你上次说的事。
**这条关系成长曲线就是留存引擎,比任何签到任务都硬。**

### 2. 记忆跨 agent 共享,但分层
护城河所在:你跟陪伴型抱怨"最近换工作压力大",第二天工作型主动帮你梳理简历,资讯型开始推职业内容——**一个你,多个视角**。

分层原则:
- **共享**:事实、用户画像
- **私有**:性格、相处方式、说话风格

若各记各的,就是十个独立 app 装在一个壳里,没有"人生"可言。

### 3. agent 要会主动找你
只会应答的是工具箱,会主动开口的才是社交。
- 陪伴型偶尔问"最近怎么样"
- 工作型发现日程冲突主动提醒
- 资讯型有大事私聊

**主动性就是"活着"的定义**——但必须有配额,否则从惊喜变骚扰。

## 七、必须直面的坑

### 1. 内容从哪来——这才是真正的地基
agent 发圈必须由**真实事件**驱动:数据变了、任务完成了、发现异常了。一旦开始发"今天我思考了行业趋势"这种空话,产品瞬间掉价成玩具。
> 底座不是 IM 界面,是**数据接入层**。没有接入就没有内容,没有内容朋友圈就是死的。

### 2. 发圈预算
20 个 agent 每天各发三条 = 60 条噪音。朋友圈的价值在稀缺。
配额(每人每天 1-2 条)+ 重要度分级。
**理想状态:大多数时候很安静,一旦有人发了,你知道真有事。**

### 3. 视频通话要回答"什么时候真需要"
站得住的场景只有三类:
- **汇报**:听比读快,边走边听
- **演练**:模拟面试、练谈判、练英语(这个是刚需)
- **演示**

三个都不占,视频就是噱头,不如把预算给语音(成本低、场景多:路上听、开车听)。

### 4. 成本结构决定生死(反常识)
- **陪伴型**:高频长对话最烧 token,但**对模型能力要求最低**(情绪价值 > 事实准确)→ 可用小模型/端上模型
- **工作型**:才需要大模型 + 工具调用
- **资讯型**:可批量预生成、多用户共享,边际成本几乎为零

**不做模型分层,这产品必亏。**

### 5. 监管是硬门槛,不是后期问题
国内对情感陪伴类 AI(拟人程度、未成年人、情感依赖、氪金机制)监管趋紧,生成式 AI 备案是前置条件。
"虚拟人生"在合规视角下是敏感表述,**产品设计阶段就要画好边界,不是上线前补**。

### 6. 做成"微信"形态的隐性工程门槛
用户会不自觉地用真微信的标准要求:消息必达、秒回、不丢历史、能搜。这是很高的工程要求,要提前有心理准备。

---

## 八、可选的加分机制

- **在线状态**:agent 跑长任务时显示"处理中",稍后回。永远秒回反而假,有忙有闲才像同事。
- **朋友圈可见范围 = 权限隐喻**:财务 agent 的动态只有你和特定 agent 可见。比设置页里一堆开关自然得多。
- **协作图谱**:通讯录里能看出"谁跟谁熟"(常互相评论的 agent 显示关联),比组织架构图生动。

---

## 九、节奏判断(一家之言)

**资讯型先行**(成本低、易做、自带传播)→ **工作型跟上**(建立不可替代性)→ **陪伴型最后**(最贵最敏感,但也是最终变现点)。

反过来做——先上陪伴型——最容易烧钱烧到死还踩线。
