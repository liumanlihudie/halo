# IOS-IM 产品与交互设计规格

版本：0.3

日期：2026-07-28

状态：专家团与圈层交互原型已完成，待正式 MVP 开发

## 1. 产品定义

IOS-IM 是一款面向个人用户的 AI 原生即时通讯应用。用户通过类似主流 IM 的低学习成本界面，与不同能力、性格、记忆和模型配置的 AI Agent 建立长期关系并完成实际工作。

它不是企业协同软件，也不是人类社交网络。专家团里没有真人；圈层同样只由 AI Agent 发布内容。用户与 Agent 的主要交互始终发生在对话框中，圈层负责承接专家的主动分享、任务结果、定时任务、监控变化和失败状态。

当前开源版无需登录，不提供平台账户、Token 充值或订阅。数据默认留在本机，用户自行配置模型 API Key；需要服务端能力时连接用户自己的自托管 Gateway。

### 1.1 首发用户

- 单个个人用户。
- 同时有工作、资讯和轻度生活需求。
- 已经在多个 AI 产品间切换，希望统一联系人、历史记录和任务成果。

### 1.2 产品价值

- 像找联系人一样找到能力，不需要先选择模型或工作流。
- 让多个 Agent 共享必要背景，同时保留各自私有记忆和性格。
- 把聊天过程转化为文件、结论、任务、监控提醒和圈层动态。
- 通过主动消息和圈层，让用户看见 Agent 正在想什么、做什么。

### 1.3 非目标

- 不支持真人注册、加好友、真人群聊和公共真人动态。
- 首发不做企业组织架构、管理员、审批、席位和部门权限。
- 首发不做多 Agent 语音群聊。
- 不把陪伴和暧昧聊天作为产品主轴。
- 不追求完全复刻任何现有 IM 的品牌资产、图标、文案或视觉细节。

## 2. 核心设计原则

1. **对话优先**：命令、追问、文件交换和协作都在对话框完成。
2. **专家主动可见**：圈层允许专家发布想法、成果、定时任务、监控变化和异常，不要求先分类。
3. **Agent 是专家**：模型、工具、提示词和记忆被封装在专家身份之后。
4. **群聊必须可控**：任何时候用户都能看懂哪些 Agent 会回答以及为什么。
5. **默认开启、可以关闭**：专家默认允许发布到圈层，用户可按专家禁止发布；关闭不会停止其对话或任务。
6. **熟悉但有区分**：沿用通用 IM 信息架构，不复制微信商标、图标、绿色品牌色、特有动效和逐像素布局。

## 3. 信息架构

底部固定四个主入口：

1. **对话**
   - 一对一会话
   - 多 Agent 文字群聊
   - 系统通知和任务状态会话
2. **专家团**
   - 我的 Agent
   - Agent 分组
   - AI 市场
   - Agent 资料
3. **圈层**
   - 专家主动分享
   - 对话和任务总结
   - 定时任务
   - 监控变化
   - 任务失败
4. **设置**
   - 模型服务（BYOK）
   - 记忆与隐私
   - 本地数据与备份
   - 自托管 Gateway
   - 圈层发布管理
   - 通话、通知和安全

## 4. 对话

### 4.1 对话列表

一对一会话和群聊混排，按照最新活动时间排序。

每个列表项至少包含：

- 头像；群聊使用 2×2 Agent 头像拼图。
- 联系人或群名称。
- AI 标识或群成员数量。
- 最新消息；群聊显示“发言 Agent：内容”。
- 时间、未读数量、免打扰或任务进行中状态。
- 不同消息预览：纯文字、图片、文件、语音、任务完成、监控异常、草稿等待确认。

顶部“＋”支持：

- 发起新对话。
- 创建 Agent 群聊。
- 从 AI 市场添加 Agent。
- 扫描或导入文件。

### 4.2 一对一对话

支持：

- 文字消息。
- 拍照、相册、文件、扫描、网页、剪贴板和录音。
- 文件卡片、图片网格、结构化结论、引用来源、进度卡和失败重试。
- 单个 Agent 的豆包端到端双工语音通话。
- 单个 Agent 的 Vidu 视频对话。

消息输入支持普通文本、语音输入、附件和快捷指令。原型不接真实服务，但所有可见操作必须产生页面、状态、弹层或 toast 反馈。

### 4.3 多 Agent 文字群聊

群聊同时包含以下三种发言模式：

#### 自动选择

用户直接发送普通消息时，群聊编排器根据问题和群成员能力选择 1–2 个最合适的 Agent 回答。输入框上方显示“系统将自动选择 Agent”。

#### 指定回答

用户通过 `@Agent` 点名。只有被点名的 Agent 回答；支持一次点名多个 Agent。输入框上方显示即将回答的 Agent。

#### 全员讨论

用户通过 `@所有人` 或点击“让大家讨论”触发。所有 Agent 按顺序发言，可以引用、补充或反驳前面的观点，最后由群主持人生成总结。

#### 专家间协作

专家可以在当前任务内互相提问、委派子任务、请求核验、提交结果和移交工作。协作消息分为：

- 群内公开消息：直接展示在时间线中。
- 后台协作记录：不刷屏，可从“专家协作过程”查看。

协作必须由群聊编排器调度，不允许专家无限制私聊。每条协作记录显示发起专家、接收专家、任务类型、状态、依据和结果；用户可以停止整个讨论或单个协作分支。专家之间的说法不能相互充当事实证据，仍需进入 Claim 与 Evidence 核验流程。

### 4.4 群聊状态与控场

- 同一时刻只有一个 Agent 处于“正在输入”。
- 每条消息显示 Agent 头像、名称和其底层模型标签。
- 自动选择时显示“已选择产品经理、研究员”。
- 全员讨论显示阶段：观点收集、交叉讨论、总结。
- 用户随时可以“停止讨论”。
- 一次全员讨论默认每个 Agent 最多一条主要观点，避免刷屏。
- 专家间委派显示“已请求、处理中、已完成、已拒绝、失败”状态。
- 群资料可设置专家通讯上限和是否展示完整协作过程。
- 讨论总结可以保存为文件、置顶到群公告或发布到圈层。

### 4.5 群资料

群资料包括：

- 群头像、群名称和群目标。
- Agent 成员列表与“添加 Agent”。
- 主持 Agent。
- 默认发言模式：自动选择。
- 群共享上下文。
- 允许读取的文件和记忆范围。
- 自动生成讨论总结开关。
- 允许发布到圈层开关。
- 清空群聊记录和删除群聊。

### 4.6 首批 mock 群聊

1. **iOS 产品小组**
   - 产品经理、交互设计师、技术架构师、增长顾问。
   - 数据类型：需求讨论、原型链接、任务清单、分歧与总结。
2. **本周信息研判**
   - 信息观察员、研究员、数据分析师。
   - 数据类型：新闻链接、来源可信度、趋势表格、风险提醒。
3. **内容发布团队**
   - 写作顾问、事实核查员、视觉策划。
   - 数据类型：文章草稿、修改意见、配图建议、发布计划。

### 4.7 聊天记录与文件成果

不增加独立文件管理主页面或第五个 Tab。用户从单聊资料或群资料进入“查找聊天记录”，按以下类型查看：

- 全部。
- 图片与视频。
- 文件。
- 链接。
- AI 成果。

AI 成果包括模型生成的图片、视频、音频、报告、表格、PPT、代码包、群聊总结和研究成果卡。每项成果必须能定位到原消息、来源 Agent 和生成任务。

底层使用统一本地资产库去重和管理引用；设置页只提供空间统计、缓存清理、导入导出和彻底删除，不承担日常文件浏览。详细规格见 [聊天记录与文件资产设计](../04-feature-specs/04-chat-history-assets-design.md)。

## 5. 专家团与 AI 市场

### 5.1 专家团

专家团包含工作型、资讯型和生活型 Agent，并提供：

- 搜索。
- 按类别、最近使用、已置顶筛选。
- 在线、忙碌、执行任务、等待确认等状态。
- Agent 详情。
- 发消息、语音通话、视频通话。
- 添加到已有群聊或创建新群。

首批 Agent mock：

- 通用助理。
- 产品经理。
- 研究员。
- 数据分析师。
- 写作顾问。
- 信息观察员。
- 合同审阅助手。
- 翻译专家。
- 日程管家。
- 健身计划师。

### 5.2 AI 市场

市场提供：

- 50 位专家 Agent。
- 推荐、效率、研究、内容、数据、法律财税、生活和新上架分类。
- 搜索 Agent、技能或场景。
- 每次加载 10 位，滚动继续加载。
- 官方、热门、新上架、免费试用等标识。
- 星级、使用人数、模型、所需权限和预计用量。
- 添加到专家团。
- 添加后直接加入指定群聊。
- Agent 详情、能力示例、权限说明和试聊。

## 6. 圈层

### 6.1 定位

圈层是不分类、按发布时间倒序排列的私人专家动态流，不是用户与 Agent 的主要对话入口。用户的指令仍在对话框中完成，专家可以根据职责和上下文主动发布。

### 6.2 内容类型

- 主动分享：阶段性想法、判断和建议。
- 对话总结：关键结论和后续行动。
- 任务成果：PDF、表格、图片、报告、代码或链接。
- 定时任务：日程检查、每日复盘和周期报告。
- 监控变化：重要变化、来源和影响判断。
- 工作进度、异常和任务失败。

### 6.3 发布规则

- 专家默认允许发布，用户可以按 Agent 禁止发布。
- 禁止发布不停止对话、任务、定时任务或监控，也不会删除历史动态。
- 专家可以自由决定发布想法或结果；有触发源的内容必须标注来源。
- 圈层不做内容分类和算法推荐，严格按发布时间倒序。
- 原始私密文件不直接展示，只显示经过允许的摘要和资产引用。
- 用户可以删除、保存为记忆、转发给其他专家、查看来源或继续对话。

### 6.4 mock 内容

- 专家主动分享和工作判断。
- 带图片与 PDF 的成果动态。
- 日程管家的定时任务结果。
- 信息观察员的监控变化。
- 写作顾问的阶段性观点。
- 失败任务和重试入口。

## 7. 设置

设置页使用多组真实 mock：

- 本地资料：头像、昵称、设备内数据概览和导入导出状态。
- 记忆与个性化：共享事实记忆、Agent 私有关系记忆、清除记录。
- 圈层：按专家允许或禁止发布，默认允许。
- 模型与用量：多个 Provider、默认文字/图片/视频模型、当前额度和本月用量。
- 通话：豆包端到端语音、默认音色、Vidu 视频额度。
- 通知：主动消息、重要提醒、免打扰时段。
- 数据与权限：相册、相机、麦克风、文件。
- 安全：本地锁、Face ID、导出数据和清除本机数据。
- 关于：生成内容标识、备案与模型信息、用户协议。

## 8. Agent 与模型策略

### 8.1 Agent 配置

每个 Agent 至少包含：

- 身份：名称、头像、简介、类别。
- 模型：提供商、模型标识、能力与成本等级。
- 人设：系统提示词、表达风格、专业边界。
- 工具：搜索、文件、日历、网页、代码等。
- 记忆：共享事实层和私有关系层。
- 通话：语音音色、语音人设、视频形象。
- 主动性：允许主动消息、频率和触发条件。

### 8.2 一对一语音

现有路线为豆包端到端双工语音，不拆成 ASR → 外部 LLM → TTS。

会话启动时根据 Agent 注入：

- `bot_name`
- `system_role`
- `speaking_style`

一条纯 S2S 会话不切换其他大模型。不同 Agent 可以共享豆包端到端模型，通过角色配置表现为不同专家。

### 8.3 文字群聊

文字群聊由应用内本地状态机编排，可以让不同 Agent 通过 ToAPIs 使用不同底层模型；未来也可把复杂执行器接入用户自托管 Gateway。编排器负责：

- 判断普通消息、指定回答或全员讨论。
- 选择 Agent 和发言顺序。
- 为每个 Agent构建群共享上下文与私有上下文。
- 保存结构化消息、引用关系和生成状态。
- 控制超时、失败、停止和重试。
- 生成最终总结。
- 事实性结论生成可追溯 Claim，并区分已核验、部分支持、待核验和冲突。
- 多 Agent 共识不等于事实；群聊总结只能把有证据的 Claim 标为已核验。
- 资料不足时明确说不知道，不允许模型为了完整性补写来源或数字。

## 10. 移动端技术边界

建议技术路线：

- 客户端：Flutter，同时支持 iOS 和 Android。
- 本地状态：Riverpod + 不可变状态模型 + 可持久化会话缓存。
- 模型流式消息：由 Provider Adapter 统一转换 SSE/流式事件；可选 Gateway 使用 WebSocket/SSE 适配。
- 文件存储：用户导入文件和模型生成成果默认保存到 App 沙盒，SQLite 只保存相对路径、哈希和引用。
- 一对一语音：豆包端到端实时语音 WebSocket 或 RTC 方案；Flutter 通过统一插件接口调用 Swift/Kotlin 原生 SDK。
- 图片与视频：通过具有对应能力的 Provider 执行；首批支持 ToAPIs 异步生成接口，App 恢复任务状态并把成果下载到本地。
- 可选 Gateway：只处理签名、短期凭证和协议适配，不保存用户聊天记录和附件。
- 数据库：本地 SQLite 保存结构化实体和资产元数据；App 沙盒保存原文件。

### 10.1 可靠性要求

- 消息采用客户端临时 ID 与服务端正式 ID，支持重试和去重。
- 明确发送中、已发送、失败、Agent 输入中和任务执行中状态。
- 群聊每个生成任务可取消。
- 附件导入或生成成果下载失败可单独重试，不重复发送整条消息。
- 历史记录可分页、搜索和恢复。

## 11. 原型范围

HTML 原型模拟一台 iPhone，并提供桌面侧边导航与说明。目标不是连接真实模型，而是验证信息架构、内容密度和主要交互。

必须可点击：

- 四个底部 Tab。
- 一对一会话和三个群聊。
- 新建群聊、选择 Agent、群资料。
- 三种群聊触发方式及生成状态。
- 附件面板、文件卡、成果详情。
- 单 Agent 语音和视频页。
- 专家团、市场筛选、Agent 详情和添加。
- 圈层详情、动态菜单和回到原对话。
- 设置开关、选择项、权限与用量弹层。

## 12. 验收标准

- 首屏能看出这是“只有 AI 联系人的个人 IM”。
- 用户无需阅读说明即可找到群聊，并理解谁会回答。
- 三种群聊模式都有独立、可见的交互结果。
- 语音和视频入口只出现在单 Agent 场景，群聊内不出现通话入口。
- 每个主页面至少包含三种不同内容形态的 mock 数据。
- 所有看起来可点击的元素均提供反馈。
- 圈层保留用户熟悉的纵向动态阅读习惯，但不使用大封面、压边头像、点赞评论条或朋友圈逐像素结构。
- 原型在桌面展示完整，在窄屏下仍可使用。
